# QuickDash Customer App - Technical Implementation Report
**Version:** 1.0.2+2
**Generated:** December 20, 2025
**Package Name:** com.quickdash.customer

---

## Executive Summary

The QuickDash Customer App is a comprehensive Flutter-based multi-service delivery platform that integrates food delivery, e-commerce, cab services, vehicle rentals, parcel delivery, and on-demand services. The application employs a modern tech stack with Firebase as the primary backend, leveraging real-time database capabilities, authentication, and cloud messaging to deliver a seamless user experience.

---

## 1. Technology Stack & Framework

### Core Framework
- **Flutter SDK**: >=3.4.3 <4.0.0
- **Dart**: Primary programming language
- **Architecture Pattern**: Mixed MVC/MVVM with GetX state management

### State Management
- **Primary**: GetX (v4.6.6) - Reactive state management, navigation, and dependency injection
- **Secondary**: Provider (v6.1.2) - Cart database management
- **Local Storage**: Moor/SQLite (moor_flutter v4.1.0) for offline-first cart functionality

### Backend & Database
- **Primary Database**: Google Cloud Firestore (Real-time NoSQL)
- **Authentication**: Firebase Authentication with multi-provider support
- **File Storage**: Firebase Storage with CDN capabilities
- **Real-time Updates**: Firebase Cloud Messaging (FCM)

## 2. Project Architecture & Structure

### Modular Architecture
The app follows a service-oriented modular architecture:

```
lib/
├── main.dart                    # Application entry point
├── AppGlobal.dart              # Global utilities and app bar builders
├── constants.dart              # App-wide constants and configurations
├── ui/                        # UI screens (feature-based organization)
│   ├── auth_screen/           # Authentication flows
│   ├── home/                  # Dashboard and main navigation
│   ├── cartScreen/            # Shopping cart management
│   ├── orderDetailsScreen/    # Order tracking and management
│   ├── mapView/               # Location-based services
│   └── payment/               # Payment processing
├── services/                  # Business logic and API services
│   ├── FirebaseHelper.dart    # Centralized Firebase operations
│   ├── helper.dart            # Common utility functions
│   └── notification_service.dart # Push notification management
├── model/                     # Data models and JSON serialization
├── controller/                # GetX controllers for state management
├── widget/                    # Reusable UI components
├── onDemand_service/          # On-demand service module
├── rental_service/            # Vehicle rental module
├── cab_service/               # Taxi/cab service module
├── parcel_delivery/           # Parcel delivery module
└── ecommerceservice/          # E-commerce module
```

### Design Patterns
- **Repository Pattern**: Implemented through FirebaseHelper for data access
- **Service Locator Pattern**: GetX dependency injection
- **Observer Pattern**: Reactive programming with GetX observables
- **Factory Pattern**: Payment gateway selection and initialization

## 3. Core Features & Implementation Details

### 3.1 Authentication System

#### Multi-Provider Authentication Implementation
- **Firebase Authentication** as the primary auth service
- **Supported Methods**:
  - Email/Password authentication
  - Phone number authentication with SMS verification
  - Google Sign-In (OAuth 2.0)
  - Apple Sign-In (for iOS devices)

- **Re-authentication**: Required for sensitive operations like password changes
- **Session Management**: FCM token-based session handling
- **Role-Based Access Control**: Customer, Vendor, Driver, and Provider roles

### 3.2 Location Services Implementation

#### Dual Map Provider Architecture
The app implements a sophisticated dual mapping system:

**Primary: Google Maps Integration**
- **SDK**: google_maps_flutter (v2.9.0)
- **Features**: Real-time location tracking, route calculation, geocoding
- **API Integration**: Google Places API for location search and autocomplete
- **Implementation**: Custom MapViewScreen with vendor clustering and proximity filtering

**Alternative: OpenStreetMap (OSM)**
- **SDK**: flutter_osm_plugin (v1.3.3+1)
- **Nominatim Integration**: osm_nominatim (v3.0.1) for address geocoding
- **Use Case**: Backup mapping solution for regions with limited Google Maps coverage

#### Location Features
- **Real-time Tracking**: Geolocator (v6.0.2) for continuous position updates
- **Geo-fencing**: Custom GeoFlutterFire implementation for vendor proximity searches
- **Place Picker**: google_maps_place_picker_mb (v3.1.2) for address selection
- **Route Optimization**: flutter_polyline_points (v2.1.0) for navigation paths

### 3.3 Payment Gateway Integration

#### Comprehensive Multi-Gateway Architecture
The app supports 10+ payment gateways for global coverage:

**Primary Gateways:**
1. **Stripe Integration** (flutter_stripe v11.1.0)
   - Credit/Debit card processing
   - Digital wallet support
   - Tokenization for PCI compliance
   - Implementation: services/stripeIntentCreateAPI.dart

2. **RazorPay** (razorpay_flutter v1.3.7)
   - Indian market specialization
   - UPI, wallet, and card support
   - Implementation: services/rozorpayConroller.dart

3. **PayPal Native** (flutter_paypal_native v2.1.0)
   - International payment processing
   - Multi-currency support
   - Implementation: services/paypalclientToken.dart

**Regional Gateways:**
4. **PayStack** - African payment processor
5. **FlutterWave** - African market coverage
6. **Paytm** - Indian digital wallet
7. **Mercado Pago** - Latin American payments
8. **Orange Money** - African mobile money
9. **Xendit** - Southeast Asian payments
10. **Midtrans** - Indonesian payment gateway

#### Payment Features
- **Wallet System**: Internal digital wallet with top-up functionality
- **Multi-Currency**: Dynamic currency conversion
- **Refund Management**: Automated refund processing
- **Transaction History**: Comprehensive payment tracking
- **Coupon System**: Discount and promotional code support
